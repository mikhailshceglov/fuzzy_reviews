# fuzzy_reviews

Интерпретируемый анализ тональности русскоязычных отзывов с использованием **нечёткой логики**.

Проект строит признаки из текста, затем применяет нечеткий вывод (Mamdani, MAX–MIN) и выдаёт **4 итоговые метрики**:

* **final_tonality** — итоговая тональность
* **trust** — достоверность оценки
* **final_emotion_intensity** — итоговая интенсивность эмоций
* **impression_strength** — сила впечатления

> Идея: вместо «чёрного ящика» мы строим прозрачный пайплайн: **словарь → признаки → правила → объяснимый вывод**.

---

## 1. Структура проекта

* `build_lexicon/` — этап 1: генерация словаря полярностей по леммам
* `feature_create/` — этап 2: извлечение числовых признаков из отзывов
* `fuzzy/` — этап 3: фаззификация, база правил, Mamdani-вывод, дефаззификация
* `data/` — данные (тексты отзывов и/или подготовленные файлы)
* `tests/` — эксперименты/оценка устойчивости словаря (графики, отчёты)

---

## 2. Коротко о методе

### 2.1 Нечёткая логика

Нечёткая логика моделирует высказывания вида «скорее хорошо», «слегка плохо», «почти идеально» с помощью **степени принадлежности** (\mu \in [0,1]).

Пайплайн вывода:

1. **Фаззификация** входов (числа → термы)
2. **Правила IF–THEN** (Mamdani)
3. **Агрегация** и **дефаззификация** (centroid)

---

## 3. Этап 1 — генерация словаря полярностей

### Зачем нужен словарь

Мы хотим интерпретируемые признаки на уровне слов. Словарь хранит для каждой леммы:

* `polarity` (\in [-1,1]) — средняя полярность контекстов
* `freq` — частота/количество контекстов

### Как строится (в общих чертах)

Отзывы → предложения → леммы → модель оценивает тональность предложений → переносим оценку на леммы → фильтруем по частоте.

### Запуск

Запускать из **корня репозитория**, скрипт находится в `build_lexicon/`.

```bash
python3 build_lexicon/build_auto_polarity_lexicon.py \
  data/rureviews_reviews.txt \
  --min-freq 50 \
  --json-out build_lexicon/rureviews_lexicon.json \
  --csv-out  build_lexicon/rureviews_lexicon.csv
```

Рекомендуемая настройка по результатам экспериментов стабильности: `--min-freq 50`.

---

## 4. Этап 2 — извлечение признаков

Цель этапа 2 — превратить отзыв в **набор числовых признаков**, которые затем подаются в нечеткую систему.

Примеры признаков (ядро):

* `pos`, `neg`, `score_crisp` — тональность по словарю
* `emotion_intensity_crisp` / `emotion_intensity_score` — сила эмоций
* `coverage`, `tokens_alpha` — информативность / покрытие словарём
* `hedges_count`, `hedges_rate` — неопределенность формулировки
* `magnitude`, `conflict` — сила оценки и противоречивость

Результат сохраняется в `features.jsonl` (1 строка = 1 отзыв).

---

## 5. Этап 3 — нечеткий вывод (Mamdani)

### 5.1 Что делает этап

На вход подаются признаки из этапа 2. Затем:

* входы фаззифицируются (термы и функции принадлежности)
* применяются правила из базы (`rules.yml`)
* агрегируются выходные функции принадлежности
* выполняется дефаззификация (centroid)

### 5.2 База правил (логика)

Мы считаем 4 выхода:

* **trust**: зависит от `coverage` и `hedges_rate`
* **final_tonality**: базово от `score_crisp`, корректируется `coverage`, `hedges_rate`, `conflict/magnitude`
* **final_emotion_intensity**: от `emotion_intensity_crisp` с уточнением через `magnitude`
* **impression_strength**: от `magnitude` и `conflict`

---

## 6. Проверка адекватности словаря (исследование)

Чтобы убедиться, что словарь не «случайный», мы пересобирали его несколько раз и сравнивали результаты.

Использовали:

* **Spearman ρ** — насколько совпадает ранжирование лемм по полярности
* trade-off **стабильность ↔ покрытие** при разных `min_freq`
* scatter `pol_A(w)` vs `pol_B(w)` и ECDF для (|\Delta|)

Вывод: при `min_freq ≈ 50` достигается хороший баланс стабильности и размера словаря.

---

## 7. Демо/типовой запуск пайплайна

Обычно пайплайн выглядит так:

1. Этап 1: собрать словарь
2. Этап 2: собрать признаки
3. Этап 3: получить 4 итоговые метрики и объяснение (термы/μ и сработавшие правила)

---

## 8. Результаты

На выходе для каждого отзыва получаем:

* 4 итоговые метрики (числа)
* распределения по термам ((\mu) по каждому выходу)
* набор сработавших правил (объяснимость)
